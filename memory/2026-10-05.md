**Bug A — WHERE 过滤时序错误**
- `WITH other WHERE r IS NULL` 的 WHERE 在 OPTIONAL MATCH 展开**之前**求值，此时 `r` 是 undefined → `r IS NULL` 恒为 true，导致本应过滤掉的行被保留。

**Bug B — 单 MATCH + OPTIONAL free source 路由错误**
- `MATCH (other:B) OPTIONAL MATCH (a)-[r]->(other)` 里 `a` 是 free source（未绑定），但单 MATCH 查询被路由到 GE 主路径，而 GE 主路径不支持 free source 展开（srcNodeIdx=-1）。
- 已修复：`src/query/query-executor.ts` 的 `_executeMultiMatchCrossJoin` 中：
  1. 新增 `_optionalHasFreeSource` 检测（~line 1110），当 OPTIONAL MATCH 的 source 不在主 MATCH 绑定的变量里，即使单 MATCH 也继续走 cross-join。
  2. `if (!mm?.length && !_optionalHasFreeSource) return null`（~line 1124）。
  3. `if (patterns.length < 2 && !_optionalHasFreeSource) return null`（~line 1155）。
  4. `mm.map` → `(mm || []).map`（两处，处理单 MATCH 时 mm 为 undefined）。

## 19:23-07:31 后续：with-orderBy [45] floats 浮点排序 bug 修复

### 根因
- `3.0` 这种「integral float literal」被解析成 `{ __float: 3 }`（保留 Cypher Float 类型，为 `1 / 2.0` 整数除法判定）。
- `_compareValues` 有 unwrap `__float`（line 3235），但 `_compareOrderByValue`（ORDER BY 排序）**没有 unwrap**，`{__float:3}` 被当 object（type rank 0 = map），排到所有 number 前面。
- 导致 `WITH ... ORDER BY value` 时 `3.0` 排最前，`orderedX = range(0, n-1)` 判定 false。

### 修复
- `_compareOrderByValue` 开头加 `__float` unwrap（镜像 `_compareValues`），`{__float:3}` 当 number 3 排序。
