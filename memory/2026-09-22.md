### With6 [4] — var-length path + path-variable + implicit grouping (DONE, 57/57)
Query: `MATCH p = ()-[*]->() WITH count(*) AS count, p AS p RETURN nodes(p) AS nodes`
- Root cause (final): `hasPathVarAgg` block in `_executeViaGraphEngine` (~line 6155)
  collapsed per-path rows into a single row with `p` as a path ARRAY when ANY
  WITH column existed (`!!(plan.with?.columns?.length)`). For a grouping key `p`
  (not a collect target), paths must stay one-row-per-path.
- Fix: narrow trigger to `(plan.with?.columns || []).some(c => /collect\s*\(/.test(c.expression))`
  (plus existing list-comprehension-over-collect check). Only true collect() triggers
  the array fold.
- Earlier fixes already committed for [4]: pathVar threading through var-length
  match (was hard-coded null), `_executeQuery` GROUP-BY post-processing skip for
  range/pathVariable steps.

### With7 [1] — WITH on WITH alias shadowing (IN PROGRESS)
Query: `MATCH (a:A)-[r:REL]->(b:B) WITH a AS b, b AS tmp, r AS r WITH b AS a, r LIMIT 1 MATCH (a)-[r]->(b) RETURN a, r, b`
- Bug A (FIXED): `_executeViaGraphEngine` multi-WITH pipeline (~line 5853) evaluated
  WITH columns SEQUENTIALLY, so `a AS b` then `b AS tmp` read the freshly-renamed `b`
  (= a/A node) instead of the original `b` (B node). openCypher WITH projections are
  SIMULTANEOUS within a single WITH clause.
  - Fix: build one `baseRc` input snapshot per WITH clause (props + __crossVarRows +
    __edges restore), then each column evaluates against a shallow copy `{...baseRc}`.
- Bug B (NOT YET FIXED): second MATCH after the WITH chain (`MATCH (a)-[r]->(b)`) is
  NOT represented in `plan` at all. `plan.steps` only holds the FIRST MATCH; there is
  no `postMatches`/`secondMatch` field. So `RETURN a, r, b` yields [] because the
  second MATCH is dropped. This is a multi-part query (MATCH ... WITH ... MATCH ...)
  gap in the parser.
- With7 [2] also fails: `count(*)` returns 0 instead of 1 (multi-WITH + predicate +
  aggregation).

## Lessons
- WITH projections are simultaneous within one clause; never evaluate sequentially
  into the same mutable props object.
- The "pre-aggregate path variable" fold must only trigger on real collect(), not on
  any WITH-column presence.
- Multi-part queries (MATCH ... WITH ... MATCH ... RETURN) are parsed with only the
  FIRST MATCH surviving into `plan.steps`; a second trailing MATCH needs dedicated
  parser + executor support (the With7 blocker, not yet implemented).
