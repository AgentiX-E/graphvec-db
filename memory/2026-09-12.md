## 本轮修复：源归属边身份（commit 88b5f620）
- **根因**：上一 commit `c8077b9d` 用"对象身份（WeakMap）"给边分配 id，导致 Match6 [9] 回归（got 2）。
  - 单语句 CREATE 用 `pushDedup`（step-definitions.ts ~line 1369-1378）把每条关系加到**两端**（src + dst 各一份对象），且三元组去重（平行边被合并）。
  - 多语句 CREATE 用 `_ensureNode`（~line 1184）只 push 到 **source** 节点，且**保留平行边**。
  - 两路径数据约定不一致，是核心矛盾。
- **修复方案**：边身份 = **源归属 + occurrence**，key = `srcIdx|dstIdx|label|occurrence`。
  - 源节点（e.srcIdx===node index）内相同 (dstIdx,label) 的第 k 条 = occurrence k（区分平行边）。
  - target 拷贝（e.srcIdx!==node index）映射到源节点 occurrence-0（合并两端存储）。安全因为两端路径 pushDedup 已去重平行边。
  - 预处理两趟：先给源归属边分配 occurrence 递增 id；再解析 target 拷贝到 occurrence-0。
- **结果**：Match6 1→0（[9] 已修 + [14] 平行边仍正确），Match3 3→1（连带）。match 目录 37→34。

## 关键技术决策与教训
- **trail 语义**：Cypher 变长路径默认允许节点重复（非 ACYCLIC），但**不允许重复关系（边）**。边身份必须区分平行边、合并两端存储。
- **两端去重 vs 平行边区分**是同一对矛盾的两面，信号 = "源节点内 occurrence"。
- 全量 clauses 回归（~1230 场景）cucumber 串行太慢 + 多进程 OOM，必须分目录/feature 跑，且用后台 + 长 poll，避免主 session 空转挂起（HARD-RULES Rule 3）。

### 新根因：`[*]` 无范围变长被解析成 NaN range
- **[13]** `(a)-[*]->(x)`：`plan.optionalMatchSteps[0].steps[0].range = {min:NaN, max:NaN}`（`JSON.stringify` 显示为 `null`，但 `typeof min === 'number'`，实际是 NaN）。
