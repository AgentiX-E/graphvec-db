### 修复的 Bug

1. **STARTS_WITH / ENDS_WITH / CONTAINS 未在 matchVarKeys2 filter 链中处理**
   - 当 WHERE 条件被编译成 plan.filters，filter 链 (varNodeMap2[x].filter()) 的 default case 只做 `String(actualVal) === String(fv)`
   - 导致空字符串 `'' STARTS WITH ''` 只匹配到空字符串节点，而非所有节点
   - Fix: 在 switch 中增加 STARTS_WITH/ENDS_WITH/CONTAINS case，使用 JS `.startsWith()`/`.endsWith()`/`.includes()`

2. **`_validateUndefinedVariables` 中变量提取未移除函数名**
   - 对 `RETURN toBoolean(b) AS b`，`b` 来自 UNWIND，但 `toBoolean` 被误判为变量
   - 导致 UndefinedVariable 报错
   - Fix: 在 RETURN 列字符串中先用正则去掉函数调用（替换为参数本身）

3. **toBoolean 函数缺失**
   - TCK 使用 `toBoolean()` 函数，但代码中只有 tostring/tointeger/tofloat
   - Fix: 在 `_builtinFunctions` 中添加 `toboolean`，处理 true/false 字符串和布尔值

4. **tointeger/tofloat 对 NaN 输入直接返回 NaN**
   - `parseInt('abc')` → NaN，但 Cypher 规范要求返回 null
   - Fix: 用 `isNaN()` 检查后返回 null

5. **OPTIONAL MATCH 绕过 GraphEngine 处理路径**
   - `OPTIONAL MATCH (n) RETURN n.missing IS NULL, n.exists IS NULL` 走了纯 RETURN 路径
   - 因为 parser 将 OPTIONAL MATCH 的 hasMatch 设为 false
   - 导致 `n` 变量无绑定，所有 IS NULL 求值为 true
   - Fix: 在纯 RETURN 路径条件中加入 `!hasOptionalMatch` 检查

6. **OPTIONAL MATCH scanLabel 未在 `_fixScanLabel` 中处理**
   - ANTLR 将 `OPTIONAL MATCH (n)` 中的 `n` 误设为 scanLabel
   - 只有主计划的 scanLabel 被修复，optionalMatchSteps 内的 scanLabel 未修复
   - 导致 GE 查不到节点（无 `:n` 标签）
   - Fix: 在 `_fixScanLabel` 中同时修复 optionalMatchSteps 的 scanLabel

7. **`_alias` 出现在节点输出中**
   - `_alias` 是内部字段，不应暴露给用户
   - toNodeNotation（step-definitions）不识别 `_alias`，将其作为普通属性输出
   - Fix: 不在 `__crossVarRows` 中设置 `_alias`；在 `_formatResultRow` 中过滤 `_alias` 和 `__` 前缀的属性

8. **OPTIONAL MATCH 后 RETURN 列需要重求值**
   - OPTIONAL MATCH 设置 `row[n] = nodeProps` 后，之前已求值的 RETURN 列（如 `n.exists IS NULL`）不会自动更新
   - Fix: 在 OPTIONAL MATCH 处理后添加重求值循环，对引用了 OPTIONAL MATCH 变量的表达式重新计算
