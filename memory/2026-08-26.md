## 2026-08-26 晚 — WITH SKIP 解析修复（3 个修复完成，working tree 未提交）

### 根因定位（本轮新增）
1. **ANTLR SKIP 节点是 `SkipContext`**（与 `LimitContext` 对称），但 `extractReturn`/`extractWith`（`src/query/ast-to-plan-v2.ts`）只处理 `LimitContext`，`skip` 硬编码 `undefined`。
2. **早退分支吞掉 SkipContext**：`extractWith` 的 walk 里 `if (name.endsWith('Context') && !['SortItemContext','LimitContext','WithClauseContext'].includes(name))` 会早退+递归+return，把 `SkipContext` 吞掉，永远到不了专门处理。修复：把 `SkipContext` 加进排除列表。
3. **promotion 双重切片**：parser 把 `with.skip` 提升到顶层 `plan.skip`（promotion 逻辑），导致 executor 用 `plan.with.skip` 切片 rows 后，`_postProcessResults`（`expression-engine.ts:4806-4807`）又用 `plan.skip` 对单行聚合结果二次 `slice(skip)` → 空数组。`LIMIT` 因单行 slice(0,limit) 无害所以此前没暴露，SKIP 有害所以暴露。

### 修复内容（3 个文件）
1. **`ast-to-plan-v2.ts` `extractReturn`**：新增 `SkipContext` 处理（`findChild(node,'IntegerLiteralContext')` 镜像 LimitContext），赋值 `skip`。
2. **`ast-to-plan-v2.ts` `extractWith`**：新增 `let skip` 声明 + `SkipContext` 处理 + `SkipContext` 加入早退分支排除列表 + return 由 `skip: undefined` 改为 `skip`。
3. **`executor-unwind-pipeline.ts`**：Step 4 聚合前 apply `plan.with.skip/limit` 切片后，**清零顶层 `plan.skip`/`plan.limit`**（仅当 `plan.with.skip/limit` 存在），防止 `_postProcessResults` 二次切片。

### 关键语义模型
- `WITH ... SKIP/LIMIT` 语义：在 WITH 层截断流，后续 RETURN 从上一步截断结果继续。
- **promotion 对 GE 路径（非 UNWIND）必要**：`query-executor.ts` 完全不读 `with.limit/skip`，只读顶层 `plan.limit/skip`。所以不能移除 promotion，只能 executor 切片后清零顶层字段。
- 顶层 `RETURN ... SKIP`（parser 直接从 RETURN 提取到 `plan.skip`，`plan.with.skip` 为 undefined）不受清零影响，`_postProcessResults` 正确处理。
