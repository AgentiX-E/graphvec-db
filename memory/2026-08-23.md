- **提交 `06bde67a`**：`fix(query): treat unary minus after an operator as negation, not subtraction`（Lambertyan，英文）。

- **修复**（expression-engine.ts:3584-3597）：跳过空白找前一个非空格字符 `_prevNonSpace`，若为运算符（`+ - * / % (`）则判定为一元负号，下推给 `_evalMulDiv`/`_evalExp`。科学计数法的 `e`/`E` guard **仍只看紧邻字符 `t[i-1]`**（不跳过空格），避免 `date - x`（变量以 `e` 结尾）被误判为 `5e-3` 科学计数法。

### ArgumentError [45] 根因（10 例，已定位未修复）
- 查询：`WITH <values> AS values WITH values, size(values) AS numOfValues UNWIND values AS value WITH size([x IN values WHERE x<value]) AS x, value, numOfValues ORDER BY value WITH numOfValues, collect(x) AS orderedX RETURN orderedX = range(0, numOfValues-1) AS equal`
- `plan.hasMatch=false`、`type=QUERY`、`withChain.length=4`、`unwind.name=values`、`aggregate=collect(x)`。
- 走 `_executeWithUnwindPipeline`（executor-unwind-pipeline.ts），由 executor-non-ge.ts:394-398 的 `_startsWithWith && !hasMatch && unwind` 守卫路由。
- 该 pipeline 只物化：①首个 `WITH [...] AS values` 列表字面量（~line 105-137）；②首个 `WITH <fn> AS ...`（~line 146，正则 `^WITH` 锚定查询开头）。中间 `WITH values, size(values) AS numOfValues` 的 `numOfValues` **从未物化** → 最终 `range(0, numOfValues-1)` 抛 ArgumentError（expression-engine.ts:1409）。
- `_preProcessAggregateWith`（executor-unwind-pipeline.ts:37）本可物化中间 WITH（用了 `_splitWithColumns` 支持多列），但其守卫（~line 91）要求 `plan.hasMatch && plan.with && (aggregate||SET||DELETE)`，此场景 hasMatch=false 被跳过。
- **修复方向**：让纯 WITH/UNWIND pipeline 也按 withChain 顺序物化所有 WITH 投影，使 numOfValues 跨 UNWIND + collect 聚合后仍可见。谨慎不破坏 MATCH+WITH+UNWIND 聚合路径 / Unwind1 / List12 / DML 回归。
