### 精确作用域模型（关键，纠正过错误理解）
- MATCH/UNWIND 引入变量入 scope。
- WITH 子句**重置** scope = 投影表达式引用的**源变量** ∪ 投影**别名**。
- WITH 的 ORDER BY 合法作用域 = 源变量 ∪ 别名（**不是**「旧 scope ∪ 别名」，否则 [19] `me.age` 漏报）。
- RETURN 的 ORDER BY 合法作用域 = 入 scope ∪ RETURN 别名（否则 [15] `rel.id` 误报）。

### 变量提取精度（避免误报）
`_extractOrderByVars` 排除：属性名（`a.num`→`a`）、参数（`$x`）、map 字面量 key（`date({year:...})`→year 非变量，用 `{...}` 剥离循环）、函数名、关键字。

### 修复的坑
1. ORDER BY 独立成行时 `_splitQueryClauses` 正确并入前置 WITH（不是独立子句）。
2. map 字面量 key 误报：`duration({months:1})` 的 months 被当变量。
3. RETURN 别名：`RETURN r AS rel ORDER BY rel.id` 的 rel 需入 effectiveScope。
4. 核心规则：「投影源变量∪别名」非「旧 scope∪别名」。

## 2026-08-22 — UNWIND 字符串字面量引号丢失修复（commit a6db1950，已推送）

### 成果
with-orderBy：214 → 218 通过；WithOrderBy1 [7]/[8]（空串排序 "null" !== "''"）转正。

### 根因
`extractUnwind`（ast-to-plan-v2.ts）对字符串字面量做 `trimmed.slice(1,-1)` 剥离引号，
把 `'.*'`→`.*`、`''`→空串、`' '`→空格，导致空串/空格无法与字面量 `''` 区分。
执行器 `_resolveUnwindList` 对裸 token 一律 `_evaluateExpression`，全部求值成 null。

### 修复
1. `extractUnwind`：字符串字面量**保留引号**存 raw text（符合 `_resolveUnwindList` 契约）。
2. `_splitListItems`：深度跟踪加 `(`，避免 `range(0, 2)` 被逗号错误切分。
3. 统一契约：`query-executor.ts`（CREATE+UNWIND 展开）和 `step-definitions.ts`（TCK seed）
   都改用权威的 `_resolveUnwindList` 还原列表值，消除重复的手动解析。

### 关键教训（契约冲突）
`unwind.list` 此前有两个消费点契约冲突：
- `_resolveUnwindList`（executor）期望「带引号 raw text」
- `step-definitions.ts`/`query-executor.ts` 期望「已剥引号的值」
统一为「保留引号 raw text + 用 `_resolveUnwindList` 还原」后，两处一致。
