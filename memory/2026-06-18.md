### 🎯 Quantifier TCK Fix (558/604 → 574/604)

**Changes to `src/query/query-engine.ts` (commit fff80c3f):**

1. **UndefinedVariable for list predicate variables** — Added extraction of list predicate iteration variables (`ALL|ANY|NONE|SINGLE x IN ...`) to the defined variables set in `_validateUndefinedVariables`. Fixes scenarios where `x` in `none(x IN [...] WHERE x.a = 2)` was flagged as undefined despite being bound by the list predicate.

2. **`none()` null handling** — Added `hasNull` tracking in quantifier evaluation. When no element matches `true` but at least one produces `null` result, `none()` now returns `null` instead of `true`. TCK requires this behavior.

3. **InvalidArgumentType for type mismatch** — Added compile-time check in `_validatePlan`: if a list predicate contains only string/boolean literals and the WHERE condition uses arithmetic operators on the iteration variable, throw `SyntaxError: InvalidArgumentType`. Covers `none(x IN ['Clara'] WHERE x % 2 = 0)` scenarios.

4. **whereBody suffix stripping** — Strip trailing `) AS alias` from captured WHERE body in `_validateUndefinedVariables` to prevent RETURN column aliases from being mis-identified as undefined variables.

5. **Pattern predicate stripping** — Added `_stripPatternPredicateSyntax` to strip graph pattern syntax from WHERE body before variable extraction, preventing false UndefinedVariable errors.

6. **Small fix** — Changed `const multiStepRaw` to `let multiStepRaw` to allow reassignment in edge walk dedup logic.
