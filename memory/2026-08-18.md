## 2026-08-18 晚间 — with-orderBy 第一轮攻坚（提交 91c52aa7）

### 成果
修复 WITH/UNWIND 场景的 ORDER BY / LIMIT / SKIP 完全失效，WithOrderBy 0/292 → 97/292。
六处协调修复（全部英文注释，已推 origin/master，零回归）：

1. **WITH promotion**（ast-to-plan-v2.ts buildQueryPlan 末尾）：plan.with.orderBy/limit/skip 提升到顶层（仅当顶层为空，RETURN 排序优先）。
2. **UNWIND 管道后处理**（executor-non-ge.ts）：_executeWithUnwindPipeline 只做展开+投影不排序，返回前套 _postProcessResults。
3. **ASCENDING/DESCENDING 方向词**（ast-to-plan-v2.ts 两处 SortItemContext）：原来只精确匹配 `DESC`，用 node.DESC()/DESCENDING() 判断。
4. **保留完整排序表达式**（SortItemContext）：原来 split 只取第一个 token，`NOT (a.bool AND a.bool2)` 被截断成 `NOT`。改用 node.expression()。
5. **复合表达式 ORDER BY 求值**（expression-engine.ts comparator）：非标识符表达式用 _evaluateExpression(expr, row) 逐行求值。
6. **NonConstantExpression 语义修正**（executor-validate-plan.ts）：原来错误地把 ORDER BY property 的 `.` 数量>2 判为非常量。改为 SKIP/LIMIT 引用变量（`SKIP n.count`）报错，常量表达式（`toInteger(rand()*9)`）合法。

### 关键数据认知
- 真正的 NonConstantExpression 语义：SKIP/LIMIT 依赖变量 → 报错；不依赖变量（rand()/toInteger(rand()*9)/常量）→ 合法。
- `ORDER BY sum(sum)` / `ORDER BY sum(a.num+a.num2)` 期望的是 **UndefinedVariable**（聚合函数里变量未定义/作用域外），不是 NonConstantExpression。
- SORT 方向词：ASC/ASCENDING/DESC/DESCENDING 四种都是合法的。
- UNWIND 列表元素 parser 存的是原始文本（temporal/列表字面量/八进制未被求值），_resolveUnwindList 需对字符串元素 _evaluateExpression。
