## 迭代：修复 MATCH (n) UNWIND RETURN n.prop 投影 null

### 目标
`MATCH (n:Person) UNWIND [10,20] AS val RETURN n.age, val` 返回 `age:null`，但 `RETURN val` 和纯 `MATCH (n) RETURN n.age`（无 UNWIND）均正常。

### 根因（三层，均定位并修复）
1. **matchVarCtx fallback 丢失变量名**：`query-executor.ts` 的 `matchVarCtx` fallback（line ~4171）只把节点属性展平成独立键（`age`/`name`），从不绑定源变量名 `n`，`n.age` 无处解析。
2. **varCtx 注入覆盖导致嵌套**：`executor-unwind-pipeline.ts` line ~305 `varCtx[stepSrc] = _nodes[0] = matchVarCtx` 把正确绑定的 `n→节点` 覆盖成 `n = {n:节点, ...}`（双重嵌套），`n.age` 取 undefined。
3. **RETURN 列投影只看 row**：Step 5（line ~1042）`_evaluateExpression(expr, row)` 只传 unwound row，看不到 varCtx 里的 `n`。

关键诊断证据：
- `matchVarCtx`（修复前）= `{"age":30,"val":{node},"name":"Alice"}`（无 `n` 键）。
- line 818「RETURN 列映射」`evalCtx={"n":{"n":{node}},"val":10}`（`n` 双重嵌套）→ `n.age=null`。
- **`query` 参数陷阱**：诊断脚本 `_executeQuery(p, nodes)` 未传第 3 参数 `query`，导致 fallback 处 `query=undefined`、`srcVar=undefined`。真实 TCK 路径 `_executeQuery(p, nodes, q)` 会传 query。诊断时必须传 query。

### 修复（3 处，commit `b3494a77`）
1. `query-executor.ts` fallback：从 query 提取 `MATCH (n)` 的源变量名，绑定 `n → rawEntry.props`（节点对象）。
2. `executor-unwind-pipeline.ts` line 305：加 `if (!(stepSrc in varCtx))` 保护，不覆盖已有绑定。
3. `executor-unwind-pipeline.ts` Step 5：`_evaluateExpression(expr, { ...varCtx, ...row })`。

- quick 回归 4/4 全绿。

## 迭代：Pattern Predicate 执行层修复（Pattern1）

### 目标
修复 `MATCH (n) WHERE (n)-[]->() RETURN n` 等 pattern predicate 在 WHERE 里的布尔求值错误。

### 成果（commit `7ae7343a`）
- **TCK 全量**：2438/2616（178 failed）→ **2456/2616（160 failed）**，+18 转正、零新增失败。
- **Pattern1 数据执行类（Matching）场景 0 → 21 passed**（[1]-[6][8][10长度2][12]-[21] 全过）。

### 四层根因（均已修复，落在 `query-executor.ts`）
1. **正则不认匿名端点**：`^\((\w+)` → `^\((\w*)`，匿名 `()`/`(:C)` 表示存在性检查而非具体节点。
2. **匿名节点定位失败**：`nodeIndexOf` 只靠 `_alias`，但匿名 CREATE 节点（`:C`/`:D`）无 `_alias` → 加 label+属性指纹 fallback（排除 `__edges`/`_alias`/`props`/`__` 前缀键）。
3. **方向语义混淆**：`edgeExistsFromTo` 与 `reachable` 里「反向边兼容」（`if e.srcIdx===ti && e.dstIdx===si return true`）把入边误判为出边 → 改严格方向（caller 按 out/in/any 换参或 OR）。
4. **过滤分支顺序错**：`_isPatternPredicate` 无条件 true 抢走结果 → 改为优先求值重写后的 `whereBodyExpr`（`whereBodyExpr && whereBodyExpr !== checkExpr` 分支前置）。

### 关键发现：真实 TCK 边数据是「脏」的
`having executed` 的 CREATE 边被 push 到**多个节点**的 `__edges`（污染/重复/含反向边）。例：`CREATE (a)-[:T]->(b)` 会把 `{srcIdx:0,dstIdx:1,REL}` push 进 a 和 b 两者的 `__edges`。因此：
- undirected（`any`）对污染天然容错（有边→true）→ [2][3] 恰好通过。
- out/in 方向必须**严格**按 `srcIdx`===cur / `dstIdx`===cur 判断，不能用 `_alias` 查找去猜反向。
- `nodeIndexOf` 需 fingerprint fallback 是因为 ctx['n'] 是无 `_alias` 的匿名节点拷贝（`{...val.props}` 浅拷贝丢了 `__edges`/`_alias`）。
