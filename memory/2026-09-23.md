### With4 [7] "Multiple aliasing and backreferencing" — FIXED (uncommitted as of flush)
Query: `CREATE (m {id: 0}) WITH {first: m.id} AS m WITH {second: m.first} AS m RETURN m.second`
→ expected `m.second = 0`, was `null`.

Two-part root cause:
1. **Wrong execution path**: `_executeViaGraphEngine` was never reached for the MATCH-less
   CREATE+WITH query — `_execNonGePaths` (executor-non-ge.ts) routed it into the pure
   WITH/UNWIND pipeline (`_executeWithUnwindPipeline`) because its first branch condition
   `(!plan.hasMatch && (plan.unwind || (plan.with && !plan.hasMatch)) && !_unwindCreatesNodes)`
   matched (no MATCH, has WITH, no UNWIND). That pipeline cannot fold map-literal WITH chains
   or resolve `m.second`.
   - Fix: added `_dmlWithNoUnwind = (type CREATE/MERGE) && createNodes.length && !unwind`,
     ANDed into the first branch (`&& !_dmlWithNoUnwind`), so CREATE+WITH falls through to
     the DML branch (`_buildDmlRows`).
2. **Missing WITH-chain projection in the DML branch**: once in the DML branch, the WITH
   map-literal projections (`{first: m.id} AS m`, `{second: m.first} AS m`) were never applied.
   - Fix added in `query-executor.ts` inside the CREATE/MERGE+returnColumns block (just before
     `const created = _buildDmlRows(plan, allNodes)`): fold `withChain` segments sequentially
     into a `withCtx`, bind each created alias by UNWRAPPING typed createNode props
     (`{prop:{type,value}}` → `{prop:value}`), evaluate each `expr AS alias` via
     `_evaluateExpression`, strip internal keys (`__*`/`_label`/`_alias`) from map results,
     and store final bindings in `(allNodes as any).__withVarMap`.
   - Added matching read in `executor-dml.ts` (`_buildDmlRows`, the `expr.includes('.')`
     branch): if the leading var is in `__withVarMap`, resolve the whole `m.second` through
     `_evaluateExpression` with the map in scope instead of scanning allNodes for the prop.
