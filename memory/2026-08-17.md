### 场景内容（非等值 join + OPTIONAL MATCH）
- [6] `MATCH (x:X) OPTIONAL MATCH (x)-[:E1]->(y:Y) WHERE x.val < y.val RETURN x,y`
- [7] 单 OPTIONAL MATCH 两步链 `(x)-[:E1]->(y:Y)-[:E2]->(z:Z)` + WHERE x.val < z.val
- [8] 两个独立 OPTIONAL MATCH：`(x)-[:E1]->(y:Y)` 再 `(y)-[:E2]->(z:Z)`

### 根因（4 个独立缺陷）
1. **CREATE 多行切分 bug**：`having executed` 的行合并只在行尾逗号处续行，导致 TCK 格式 `CREATE\n (:X)-[:E1]->(:Y),\n (:X {val:6})` 中裸 `CREATE` 被当成空语句推送、节点模式丢失 → `st.nodes=[]`。修复：`step-definitions.ts` 新增 `_isBareClauseKeyword()`，把单独成行的裸关键字（CREATE/MERGE/MATCH/DELETE/DETACH DELETE/SET/REMOVE/RETURN/WITH/UNWIND/OPTIONAL MATCH）当作续行前缀。
2. **MATCH 变量提取泄漏进 OPTIONAL MATCH**：`matchSection`/`allMatchVars` 正则把 `OPTIONAL MATCH ...(y:Y)` 当第二个 MATCH 变量，推入无边笛卡尔积分支 → 0 行。修复：正则止步 alternation 加 `\s+OPTIONAL`。
3. **OPTIONAL MATCH 源节点只按 label 解析**：`x=X{4}` 每次从第一个 X 节点（val:1）出发。修复：`query-executor.ts` ~line 3819 起改为「引用相等 `allNodes.indexOf` → 全属性内容匹配 → _alias → label」四级回退；并新增 `row[sourceVar]` 为对象（node-props）时的处理（label + 非下划线属性全匹配）。
4. **OPTIONAL MATCH 空值填充错误**：不匹配时把 MATCH 已绑定 source `x` 也置 null，且只绑定第一步 target 漏中间跳。修复：~line 3910 起重写为 `optBoundVars` 收集链上每个 targetAlias（含中间跳）+ source≠MATCH source 的步 source，走完整 chain 绑定，保留 source，非匹配时只置空 optional 变量。

### 关键数据结构认知
- `_walkMultiSteps(startIdx, steps, allNodes)` 返回 `number[][]`，每路径 = `[srcIdx, hop1, hop2, ...]`（完整节点序列）。第 i 步的 target 节点在 `path[i+1]`。
