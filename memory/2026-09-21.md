## 本轮定位并修复的三个根因

### 1. ORDER BY 引用 WITH 别名的原变量名（作用域丢失）
- `ORDER BY a.name + 'C'`（在 `WITH a.name AS name` 之后）里，`a.name` 应解析为别名 `name`。
- 修复：`_postProcessResults` 的 comparator composite 分支，从用原始 `expr`（`a.name + 'C'`）求值，改为用 `_orderByField` 剥离前导变量后的 `field`（`name + 'C'`）求值。
- 位置：`src/query/expression-engine.ts` comparator（约 line 5473-5484）。

### 2. `_exprCache` 缓存污染（严重 bug）
- `_evalAndCache` 判断「无 row 依赖的纯常量表达式」时用关键字黑名单，**误把 `name` 列入关键字**，导致 `_evalBinary('name', {name:'C'})` 首次缓存 "C"，后续 `{name:'A'}` 命中缓存仍返回 "C"。
- 修复：从黑名单移除 `name`（它是合法用户变量名）。
- 位置：`src/query/expression-engine.ts` `_evalAndCache` 的 `kw` 数组（约 line 2837）。

### 3. ORDER BY 混用聚合 + 未命名投影 → AmbiguousAggregationExpression（[20]）
- `ORDER BY me.age + you.age + count(*)`（`WITH me.age + you.age, count(*) AS cnt`，第一列无别名）规范要求报 `AmbiguousAggregationExpression`。
- 修复：`executor-validate-plan.ts` ORDER BY 校验块内，收集 `namedGroupKeys`（`expr AS alias` 的 expr 集合）+ `projectedAliases`，剥离字符串字面量 + 聚合调用后，剩下的裸标识符若既非命名分组键也非别名，则抛错。
- 关键：按长度降序剥离命名分组键，避免 `me.age` 被 `me` 先匹配；保证 [18]（`me.age AS age` 命名分组键 + 聚合）仍合法。
