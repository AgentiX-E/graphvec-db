### UNWIND 字符串字面量引号丢失修复（commit a6db1950，已推送 master）

#### 成果
- with-orderBy TCK：214 → **218** 通过
- WithOrderBy1 [7]/[8]（空串排序 `"null" !== "''"`）转正

#### 根因（精确定位）
`extractUnwind`（ast-to-plan-v2.ts ~2009）对字符串字面量做 `trimmed.slice(1,-1)` 剥离引号：
- `'.*'`→`.*`、`''`→空串、`' '`→空格
- 空串/空格无法与字面量 `''` 区分
- 执行器 `_resolveUnwindList`（query-parser.ts:1431）对裸 token 一律 `_evaluateExpression`，全部求值成 null

#### 修复（契约统一）
1. `extractUnwind`：字符串字面量**保留引号**存 raw text（符合 `_resolveUnwindList` 契约）
2. `_splitListItems`（ast-to-plan-v2.ts:18）：深度跟踪加 `(`，避免 `range(0, 2)`、`date({...})` 被逗号错误切分
3. **统一两个消费点**（关键）：
   - `query-executor.ts`（CREATE+UNWIND 展开，~608 行 elem 还原）
   - `step-definitions.ts`（TCK seed，~1010 行 UNWIND 列表手动解析）
   - 两者都改用权威的 `_resolveUnwindList`，消除重复手动解析

#### 关键教训：`unwind.list` 契约冲突
此前两个消费点契约冲突：
- `_resolveUnwindList`（executor）期望「带引号 raw text」
- `step-definitions.ts` / `query-executor.ts` 期望「已剥引号的值」

单纯改 `extractUnwind` 保留引号 → 引入 Comparison3 [5]-[8] 回归（`UNWIND ['a','b','c'] AS c CREATE ({name:c})` 节点 name 变成带引号 `'a'`）。
必须同步统一两处还原逻辑才能零回归。

## 2026-08-22 — Temporal 排序 + 低年份构造修复（commit c6725353，已推送）

### 成果
- with-orderBy 218 → **240** 通过（+22）
- temporal 表达式 TCK 1004/1004 全绿（零回归）
- WithOrderBy1 [15]-[20] temporal 排序全部转正

### 两类根因
1. **year 0-99 映射错误**：`new Date(Date.UTC(1,0,1))` 把 year=1 折叠成 1901
   （JS Date 构造器对 0-99 年份做 1900+year 映射）。Cypher 合法使用低年份，
   `date({year:1})` 应返回 `0001-01-01` 而非 `1901-01-01`。
   修复：`_utcDateFromYmd`（用 setUTCFullYear 构造，不做折叠），
   `_resolveDateFromMap` 全部改走它；`_fmtUtcDate` 统一 year 补零 4 位。
2. **带时区 temporal 排序用字符串比较**：time/datetime 应按 UTC 绝对时刻排序，
   而非本地时钟文本。`12:31:14+01:00`(UTC 11:31:14) 应排在 `12:30:14+00:15`(UTC 12:15:14) 前。
   修复：`_temporalSortKey` 把带时区值归一化到可比 UTC key，
   `_postProcessResults` 的 comparator 在两侧都是 temporal 时用它比较。

### 关键认知
- comparator 拿到的值是**字符串**（temporal 函数本身返回字符串，类型信息已丢失），
  只能靠正则识别 `YYYY-MM-DDTHH:MM:SS...±HH:MM`（datetime）和
  `HH:MM[:SS]±HH:MM`（time，秒可选）来判定「带时区 temporal」。
- date/localdatetime 无时区，字符串比较天然正确，无需归一化。

### 附带清理
- 删除遗留 debug：`console.log('=== DUR DATE+TIME ===')`（2138 行）、
  `console.error('T8_PLUS_DUR: ...')`（3568 行），它们污染 cucumber --format json 输出。

### 关键规则（从 TCK 反推）
`[] < ['a'] < ['a',1] < [1] < [1,'a'] < [1,null] < [null,1] < [null,2]`
→ 跨类型层级：**string < number < null**（null 排最后 = NULLS LAST，与直觉「null 最小」相反）

### 重要边界
- `_compareValues`（三值谓词逻辑，WHERE 用）**未动**，避免破坏列表 `<`/`>` 比较。
- 排序和谓词比较是两套语义：排序要总顺序（null 有确定位置），谓词要三值（null 传播）。
