## UNWIND + 顶层聚合 修复完成（2026-08-25 20:26 GMT+8）✅

### 提交 `4ab7f45e`（Lambertyan，全英文）

### 三层根因（均在 `executor-unwind-pipeline.ts`）

1. **Step 4 入口条件过严**：`plan.aggregate && !plan.with?.columns?.length` 把「WITH 列表字面量投影非空」误当「聚合已处理」，导致 `UNWIND xs AS x RETURN count(x)` 被跳过。修复：`_step4Eligible = _hasUnwind ? !_withHasAggCol : !plan.with?.columns?.length`（仅 UNWIND 场景、且 with.columns 无聚合列时执行 Step 4）。

2. **输出键名不匹配**：无 alias 的 `RETURN max(x)`，parser 把 agg.alias 设成 `max`（去掉 `(x)`），但 returnColumns 是 `max(x)`，TCK 比较时取不到键（`{max(x): null}`）。修复：`_rc0IsAgg` 时优先用 `returnColumns[0]`。

3. **max/min 只支持数字**：原用 `Number()` 过滤 + `Math.max/min`，字符串/列表/混合类型全被 NaN 丢弃成 0。修复：专用 `_aggCompare` + `_aggTypeRank`（list=0 < string=1 < boolean=2 < number=3，符合 Cypher 值层次）。

### 关键教训（重要！）

- **`_orderByTypeRank` 不能乱改**：我第一版直接改了全局 `_orderByTypeRank`（boolean/string/number/list 顺序），让 Aggregation2 转正，但引入 with-orderBy **4 个回归**（[21]/[22] distinct types、[15]/[16] time expression 等）。根因：`_orderByTypeRank` 的 `default: 50` 把 map/node/rel/list/path 结构类型都归一类，无法区分；且修改它影响全局 ORDER BY。**回退**，改用**局部** `_aggCompare` 仅影响聚合 max/min。
- **并发污染误判**：同时跑多个 cucumber-js 进程会互相干扰（`_geInstanceRegistry` 缓存残留），导致 MatchWhere/Comparison3 出现「假回归」。必须**串行**跑，或跑完先 pkill 清理。单独重跑即恢复通过。
- **Cypher 权威值层次**（Neo4j 官方）：MAP < NODE < RELATIONSHIP < LIST < PATH < VECTOR < POINT < temporal... < STRING < BOOLEAN < INTEGER/FLOAT，null 最后。聚合 max/min 需遵循此序（list 最小，number 最大）。
