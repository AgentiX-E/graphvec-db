## 执行摘要

AgentiX GraphVec 已在纯 TS 嵌入式图数据库领域打下坚实基础，与四大竞品在 10 个维度全面对比后，**核心差距**集中在：

1. **存储引擎**: OverGraph LSM-Tree 非原生图存储 → 无免索引邻接 → 邻居查询 10-100x 慢于 Neo4j
2. **Raft 不完整**: InstallSnapshot 缺失 + 成员变更不支持 + 无 pipeline 复制 → 非生产级
3. **查询语言**: 无聚合/UNION/路径返回 → 与 Cypher/Gremlin 差距明显
4. **优化器脱节**: QueryOptimizer 分析结果不驱动执行器 → 空摆设
5. **WAL 不安全**: 无 fsync + 全内存存储 → 宕机丢数据
6. **安全**: 无用户/角色持久化 + 无认证中间件 + 无加密
7. **导入**: 完全串行逐行 upsert → GB 文件不可用
8. **重平衡**: reshard-worker `execute()` 不迁移实际数据

**差异化优势**仍需强化: CRDT 多活(唯一), 纯 TS 嵌入式(唯一), Fluent API 链式风格

## 第一部分: P0 — 必须立即修复 (19 项)

### A. 存储+索引层 (4项)

### [S01] 缺少原生图存储（免索引邻接）
- **模块**: `src/core/graph-engine.ts`
- **对比**: Neo4j ✅链表式磁盘布局 / Dgraph ✅三元组谓词索引 / ArangoDB ⚠️文档引用边 / JanusGraph ✅BigTable邻接表
- **问题**: OverGraph 是 LSM-Tree 通用 KV 存储，非原生图存储。邻居查询需通过 `neighbors()` API 而非直接指针跳转，导致 10-100x 额外 I/O。
- **方案**: 在 GraphEngine 之上构建**邻接缓存层**（Adjacency Cache）：
  - `Map<NodeId, Set<EdgeRecord>> outEdges + inEdges`
  - LRU 缓存热点节点的邻接列表（默认 10000 节点）
  - upsertEdge/deleteNode 同步更新缓存
  - 冷数据降级到 OverGraph
  - **估算**: 3-5 天（纯 TS，零额外依赖）

### [I01] 缺少 Schema 索引
- **模块**: `src/index/composite-index.ts` + `src/core/label-index.ts`
- **对比**: Neo4j ✅Schema索引(唯一性约束+节点键) / Dgraph ✅@index 自动索引全部谓词 / ArangoDB ✅持久化索引 / JanusGraph ✅复合+混合索引
- **问题**: 无唯一性约束、无 Schema 级别的索引声明、无自动索引创建。复合索引需手动构建。
- **方案**: 
  - 在 `GraphConfig` / `types.ts` 中加 `SchemaIndexDef` 类型
  - `GraphEngine` 启动时根据 schema 自动创建 CompositeIndex
  - upsertNode 前唯一性约束检查
  - **估算**: 2-3 天

### [I02] 全文搜索引擎纯 JS 实现，大文档集会 OOM
- **模块**: `src/search/fulltext.ts`
- **对比**: Neo4j ⚠️Lucene(Schema索引+全文+向量) / Dgraph ⚠️Bleve / ArangoDB ✅IResearch(MMFiles持久化)
- **问题**: 倒排索引全在 `Map<string, Map<string, Map<number, ...>>>` 中，100万文档时内存爆。无分段合并机制，analyzer 链不可扩展。
- **方案**:
  - **短期**: 增量索引 + 分段合并（类比 Lucene 的 Segment）
  - **长期**: 迁移到 SQLite FTS5（WASM 实现，零额外编译依赖）
  - **估算**: 短期 5 天 / 长期 2 周

### [A02] 大量关键算法缺失
- **模块**: `src/core/graph-algorithms.ts`
- **对比**: Neo4j GDS ✅55+算法 / ArangoDB ✅6+Pregel / Dgraph ❌无内建 / JanusGraph ❌无内建
- **问题**: AgentiX 当前 11 个算法(PageRank, PPR, Louvain, TriangleCount, Jaccard, Betweenness, BFS, DFS, DFSAll, ShortestPath, AllShortestPaths)，缺失:
  - **中心性**: Eigenvector Centrality, Closeness Centrality, Harmonic Centrality
  - **社区**: Label Propagation, SCC, WCC, K-Core, Leiden
  - **路径**: A* Search, K-Shortest Paths (Yen), Hamiltonian Path
  - **相似性**: Cosine Similarity (节点向量), Pearson Correlation
  - **嵌入**: Node2Vec, DeepWalk (或近似: 随机游走嵌入)
- **方案**: 用 Worker Threads 并行运行 A*、SCC、Label Propagation、K-Shortest Paths。每个算法 80-150 行 TS。
- **估算**: 14 天（7 个算法各 2 天）

### B. 分片+共识层 (5项)

### [RH-01] Reshard 数据迁移未实现（空壳）
- **模块**: `src/reshard/reshard-worker.ts`
- **对比**: Dgraph ✅在线自动分片迁移 / ArangoDB ✅企业版自动重平衡 / JanusGraph ✅BigTable自动平衡
- **问题**: `execute()` 不执行实际数据迁移，仅比较 `nodeCount±10%` 就判定"迁移完成"。数据一致性完全无保证。
- **方案**: 
  - 实现实际数据迁移：扫描源 range 的所有节点 → 筛选属于目标 range 的节点 → upsert 到目标 range → 确定成功后从源 range 删除
  - WAL 双写确保迁移不丢数据
  - **估算**: 5-7 天

### [R-02] 快照不包含状态机数据
- **模块**: `src/consensus/raft-core.ts` 的 `_doSnapshot()`
- **对比**: Neo4j ✅因果集群快照/JanusGraph ✅后端原生快照
- **问题**: `_doSnapshot()` 只写 `{ lastIncludedIndex, lastIncludedTerm }` 到 snapshot 文件，不包含 GraphEngine 状态机数据。WAL 截断后重启，状态机数据永久丢失。
- **方案**: 
  - `_doSnapshot()` 回调 `GraphEngine.serialize()` 写入 snapshot
  - `applySnapshot()` 时从 snapshot 恢复 GraphEngine
  - 需 RaftCore 持有 engine 引用（或通过回调 interface）
  - **估算**: 3-5 天

### [R-03] InstallSnapshot RPC 未实现
- **模块**: `src/consensus/raft-core.ts`
- **对比**: Raft 规范 ✅ InstallSnapshot（所有生产级实现）
- **问题**: `requestVote` 检查 `lastLogTerm < lastSnapshotTerm` 时 follower 无法追赶。落后 follower 永久掉队。
- **方案**: 
  - 实现 InstallSnapshot RPC 处理（leader 发送 / follower 接收 + 应用）
  - 流式传输 snapshot chunk（避免大 snapshot 阻塞）
  - **估算**: 5-7 天

### [R-01] 不支持运行时成员变更
- **模块**: `src/consensus/raft-core.ts`
- **对比**: Neo4j ✅因果集群节点增删 / Dgraph ✅成员变更 / ArangoDB ✅SmartGraph节点
- **问题**: 集群扩容/缩容需重启所有节点。Raft 成员变更算法（单步/联合共识）未实现。
- **方案**: 实现 Raft 成员变更（单步变更，C_{new} 直接替换 C_{old}，适合 3-5 节点小集群）
- **估算**: 5-7 天

### [W-02] WAL append 不执行 fsync
- **模块**: `src/consensus/wal.ts`
- **对比**: Raft 规范 ✅ 写入介质确认后才应答 / Neo4j ✅事务日志 fsync
- **问题**: `append()` 写入 `fs.writeSync()` 后不调用 `fs.fsyncSync()`。数据缓存在 OS page cache，宕机丢数据。不满足 Raft 持久化安全性。
- **方案**: `append()` 追加 `fs.fsyncSync(fd)`，优化：批量 append → 一次 fsync（Group Commit 风格）
- **估算**: 1 天

### C. 查询+API层 (3项)

### [Q-01] 缺少聚合功能
- **模块**: `src/api/fluent.ts`
- **对比**: Neo4j Cypher ✅`RETURN count(n), avg(n.age), group by` / Dgraph DQL ✅`count(), min(), max()` / ArangoDB AQL ✅`COLLECT + agg` / JanusGraph Gremlin ✅`count(), group(), fold()`
- **问题**: Fluent API 无法分组/聚合/计数。`count()` 内部 `execute().length` 全量查询后再计数，无数据库级 COUNT 优化。
- **方案**: 
  - 新增 `groupBy(field)` → `aggregate(field, op)` → 返回 `AggregateResult[]`
  - 新增 `count()` 优化：不走 execute() 全量查询
  - **估算**: 3-5 天

### [Q-02] 缺少 UNION/DISTINCT/集合运算
- **模块**: `src/api/fluent.ts`
- **对比**: Neo4j ✅`UNION, UNION ALL` / Dgraph ✅Block组合 / ArangoDB ✅子查询+UNION / JanusGraph ✅`union(), dedup()`
- **方案**: 纯 TS 实现集合运算（Set<NodeRecord> 去重），`union(q2)`, `intersect(q2)`, `except(q2)` 在 Fluent API 层面
- **估算**: 2-3 天

### [QO-01] 优化器"只说不做"——不驱动实际执行
- **模块**: `src/api/query-planner.ts`
- **对比**: Neo4j ✅CBO 覆盖索引选择和 join/scan 顺序优化 / ArangoDB ✅优化器真正下推 filter/limit/sort
- **问题**: `QueryOptimizer.optimize()` 生成的优化计划仅在 `EXPLAIN` 中展示，`FluentAPI.execute()` 不采纳。统计信息收集器`StatisticsCollector` 只有 `findNodesByType` 返回数量，`distinctPropValues` 始终为空 Map。
- **方案**:
  - 真正实现谓词下推：`execute()` 读取 `optimizedPlan` 决定执行路径
  - 实时统计信息收集（scan 时扫描 prop 分布）
  - **估算**: 5-7 天

### D. 运维+安全+导入 (7项)

### [S-01] 无用户/角色持久化存储
- **模块**: `src/security/auth.ts`
- **对比**: Neo4j ✅完整 RBAC+LDAP / Dgraph ✅Guardian+ACL / ArangoDB ✅集合级权限
- **方案**: 用户/角色 JSON 文件 + `auth.json` 配置。`Authenticator` 启动时加载到内存，每次认证查表。
- **估算**: 3-5 天

### [S-03] 无 API 认证中间件
- **模块**: `src/api/rest.ts`
- **对比**: Neo4j ✅所有API强制认证 / Dgraph ✅JWT/API Key / ArangoDB ✅Bearer Token
- **问题**: `rest.ts` 中路由声明时 auth:true/false 可选，默认 false。REST API 无强制认证路径。
- **方案**: 认证默认全开，白名单例外
- **估算**: 1 天

### [S-05] 传输层和存储层均无加密
- **模块**: `src/api/rest.ts`
- **对比**: Neo4j ✅TLS/Bolt加密 / Dgraph ✅TLS/mTLS / ArangoDB ✅TLS
- **方案**: HTTPS 支持（`https.createServer` + 可选证书配置），WAL 文件级加密可选
- **估算**: 2-3 天

### [B-01] 备份无一致性快照保障
- **模块**: `src/ops/backup.ts`
- **问题**: `cpSync` 文件级复制无一致性快照，备份过程中写入的数据导致不一致。
- **方案**: 备份前检查是否有活跃写入（通过 Mutex），备份期间暂停新写入（短期）或使用文件系统快照（长期）
- **估算**: 2-3 天

### [I-01] 导入完全串行逐行 upsert，GB 级文件不可用
- **模块**: `src/import/graph-import.ts`
- **对比**: Neo4j ✅neo4j-admin import(批量) + LOAD CSV(流式) / Dgraph ✅bulk loader(batch写入) / ArangoDB ✅arangoimport
- **问题**: 630 行代码零并发。使用 `fs.readFileSync` 读入内存，GB 级文件 OOM。RDF 解析靠粗糙正则。
- **方案**: 流式读取(`fs.createReadStream` + `readline`) + 并发 upsert（`batchSize: 1000`, `concurrency: 10`）+ batch commit
- **估算**: 5-7 天

### [MV-02] 无事件总线/pub sub
- **对比**: Neo4j ✅Transaction Events+APOC trigger / Dgraph ✅Subscription / ArangoDB ✅Foxx Queue+Collection Event
- **问题**: 全系统无事件机制。物化视图只能全量轮询刷新，无法增量更新。
- **方案**: 轻量 EventBus（TS `EventEmitter`），`upsertNode/upsertEvent/deleteNode` 时 emit。物化视图订阅事件增量更新。
- **估算**: 3-5 天

### [S-04] 默认配置无强制安全校验路径
- **方案**: `start()` 时检测：如果 `process.env.NODE_ENV==='production' && !config.auth` 则拒绝启动
- **估算**: 1 天

### 差异化优势分析

**AgentiX 当前唯一的竞品差异点（4个→应强化至7个）**：

| 差异点 | 状态 | 强化方向 |
|:-------|:----|:---------|
| **CRDT 多活** ✅ | 唯一纯TS实现 | 3way merge + resolver 插件 |
| **纯TS嵌入式** ✅ | 竞品全是Java/Go/C++ | 包体积优化(<400KB), 加载<100ms |
| **Raft分片** ✅ | 嵌入式中最完整 | 修复3处(P0)即达生产级 |
| **Fluent API** ✅ | 独特链式风格 | 聚合+UNION+路径后对标Cypher |
| → **EventBus增量** | 可推 | 竞品中无轻量 TS EventBus |
| → **Worker泛化** | 可推 | 竞品无 TS 级 Worker 并行 |
| → **零摩擦部署** | 可推 | npm install + 一行代码启动 |

## 附录: 差异化优势演化

### 当前差异化 (4个)
1. **CRDT 多活** — 唯一纯TS多活图DB
2. **纯 TS 嵌入式** — 无JVM/Go runtime 依赖
3. **Raft 分片集群** — 嵌入式中最完整
4. **Fluent API** — 独特链式风格

### 目标差异化 (7个)
5. **EventBus 实时能力** — 轻量 TS EventBus 增量更新
6. **Worker 并行泛化** — 纯 TS 级 Worker 并行化
7. **零摩擦部署** — `npm i agentix-graphvec && serveGraph()` 即可运行

### 推荐定位
**"纯TypeScript图数据库 —— 嵌入式、多活、零摩擦"**
对标：Neo4j(gRPC/大规模集群、完整) ← AgentiX(嵌入式/microservices/边缘计算)
